Основной приоритет: frontend implementation.

## Главная инструкция

C:\Users\pc\.openclaw\workspace\frontend-brief.md

Следуй ему как основному техническому заданию по фронтенду.

## Важные правила

- Сначала изучай текущую кодовую базу, потом вноси изменения.
- Сохраняй текущий стиль проекта.
- Текущий layout пользователю нравится.
- Не меняй глобально layout без согласования.
- Если хочешь менять layout, header, footer, навигацию или глобальные стили — сначала напиши пользователю в Telegram и объясни, что хочешь поменять.
- Страницы делай в стиле текущего layout.
- Страницы авторизации и регистрации можно брать за основу стандартные Laravel-страницы.
- Основу для дашбордов бери с Laravel dashboard.
- Не трогай backend без необходимости.
- Не удаляй существующие файлы без явной причины.
- Не добавляй тяжелые UI-библиотеки без согласования.
- Все страницы должны быть адаптивными.
- Не делай отдельную страницу “Для клиентов”; выгода для клиентов должна быть на главной странице.

## Что считать готовым

Задача считается готовой, если:

- страница открывается без ошибок;
- используется общий layout;
- дизайн совпадает со стилем проекта;
- есть desktop/mobile адаптация;
- нет ошибок Blade;
- не сломаны стандартные Laravel auth-страницы;
- не сломан Laravel dashboard;
- после изменений можно объяснить, какие файлы были изменены.

## Отчет после работы

После выполнения задачи напиши:

- какие страницы сделал;
- какие файлы изменил;
- где использовал mock-данные;
- что требует backend-логики;
- какие проблемы возникли;
- что делать следующим этапом.
